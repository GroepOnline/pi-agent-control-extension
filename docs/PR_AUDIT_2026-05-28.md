## 🚨 Blocking Issues (Must Fix Before Merge)

### 1. Path Traversal in `skillDiff` + `skillInfo` (`index.ts`) — **CRITICAL**

Both functions accept raw user input and construct filesystem paths without validation:

```ts
// extensions/pi-control/index.ts
function skillDiff(args: string) {
  const name = args.trim();           // ❌ unsanitized
  const piPath = join(repoRoot, "skills", name, "SKILL.md");
  // ...
}
```

**Attack:** `/skill-diff ../../.ssh/id_rsa` → `join(repoRoot, "skills", "../../.ssh/id_rsa", "SKILL.md")` normalizes to `repoRoot/.ssh/id_rsa/SKILL.md` — outside the skills directory.

**Fix:** Re-use the existing `isValidSkillName()` guard from `skill-merge.ts`:

```ts
import { isValidSkillName } from "./skill-merge.ts";

function skillDiff(args: string) {
  const name = args.trim();
  if (!isValidSkillName(name)) return `Invalid skill name.`;
  // ...
}
```

Same fix required for `skillInfo()`.

---

### 2. Bridge Token Leaked to UI / Logs (`bridge.ts`) — **HIGH**

The WebSocket auth token is emitted in plaintext via `ctx.ui?.notify`:

```ts
// extensions/pi-control/bridge.ts
ctx.ui?.notify?.(
  `## Bridge Started\n\n- Port: ${actualPort}\n- Token: \`${token}\`\n- URL: ws://localhost:${actualPort}?token=${token}`,
  "info",
);
```

**Risk:** Token exposed in session logs, screenshots, shared Tmux captures, and potentially cloud sync.

**Fix:** Mask the token or instruct reading from file:

```ts
ctx.ui?.notify?.(
  `## Bridge Started\n\n- Port: ${actualPort}\n- Token: *** (read from ${BRIDGE_TOKEN_PATH})\n- URL: ws://localhost:${actualPort}?token=<TOKEN>`,
  "info",
);
```

---

### 3. Bridge Binds to All Interfaces (`bridge.ts`) — **HIGH**

```ts
httpServer.listen(port);  // ❌ binds 0.0.0.0
```

**Risk:** Any device on the network can reach the bridge. Combined with token exposure, this is a significant attack surface.

**Fix:** Bind to localhost only:

```ts
httpServer.listen(port, "127.0.0.1", () => { ... });
```

Also add `Origin` header validation on WebSocket upgrade for defense in depth.

## ⚠️ High-Priority Issues (Fix in Follow-up)

### 4. Naive 3-Way Merge Algorithm (`skill-merge.ts`) — **MEDIUM**

The `threeWayMerge()` function does a **character-by-character line comparison** without a real diff algorithm (no patience diff, Myers diff, etc.).

**Consequence:** Any line insertion/deletion causes **every subsequent line** to be marked as a conflict, even if content is identical. For Markdown files with YAML frontmatter, this is especially brittle.

**Recommendation:**
- Short-term: Document this limitation prominently in `SKILL.md`
- Long-term: Integrate `diff-match-patch` or `jsdiff` for proper diff/merge

---

### 5. No Payload Size Limits in Bridge (`bridge.ts`) — **MEDIUM**

```ts
socket.on("message", (data) => {
  const msg = JSON.parse(data.toString());  // ❌ no max length check
  // ...
});
```

**Risk:** A malicious or buggy client could send a multi-gigabyte payload causing OOM.

**Fix:** Reject messages > 1 MB before parsing:

```ts
if (data.length > 1024 * 1024) {
  socket.close(1009, "Message too large");
  return;
}
```

---

### 6. Latent Shell Injection in Capture Command Strings — **LOW-MEDIUM**

`captureBrowser`, `captureTuiStory`, and `captureTrueInput` build shell-like strings for display:

```ts
result.command = `agent-browser open ${target} --viewport 1280x720 && ...`;
```

These are **not executed** today (actual execution uses `execFileSync`), but they are stored and displayed. If a future refactor accidentally executes `result.command` via `exec()` or `spawn(..., { shell: true })`, this becomes an immediate RCE.

**Fix:** Store structured command arrays instead:

```ts
result.commandParts = ["agent-browser", "open", target, "--viewport", "1280x720"];
result.command = result.commandParts.join(" ");  // for display only
```

## 🟡 Medium-Priority Issues

### 7. `renderShowcase` Output Path Not Restricted (`remotion/src/render.ts`)

```ts
const absoluteOutPath = resolve(process.cwd(), outPath);
```

`outPath` comes from CLI args. While `showcaseRender()` in `index.ts` has a basic `hasPathTraversal` check (`..` and `/`), it does not prevent writing to arbitrary locations within the project tree.

**Recommendation:** Validate that `absoluteOutPath` starts with `process.cwd()` or is inside `artifacts/showcases/`.

---

### 8. `execAsync` Loses Error Prototype (`index.ts`)

```ts
reject({ ...err, stdout, stderr });
```

This spreads an `Error` object into a plain object, destroying the prototype chain. Callers checking `instanceof Error` or relying on `.stack` formatting will get broken behavior.

**Fix:**

```ts
const e = new Error(err.message);
(e as any).stdout = stdout;
(e as any).stderr = stderr;
(e as any).code = err.code;
reject(e);
```

---

### 9. `fs.watch` Resource Leak Risk (`studio/hooks/useSkillRegistry.ts`)

```ts
const watchers = dirs.map((dir) =>
  watch(dir, { recursive: true }, () => { ... })
);
```

`fs.watch` on Linux uses `inotify` watchers, which have system-wide limits (default ~8192). No error handling for `EMFILE` / `ENOSPC`. Multiple instances of the TUI could exhaust limits.

**Recommendation:** Add `try/catch` around `watch()` and fall back to polling or manual reload.
